# Football Match Prediction

Predict international football fixtures: pick two national teams, get outcome
probabilities, expected goals and a scoreline distribution.

## Agreed plan

Full plan: `~/.claude/plans/let-s-develop-a-front-end-streamed-spark.md`.
The decisions below are settled — follow them rather than re-deriving.

**Done**
- `model.py` — the served model. `get_model().predict(home, away, neutral, tournament)` returns the whole API payload.
- `test_model.py` — assert-based checks, no framework. Run before touching model maths.
- `api.py` — FastAPI, `GET /api/teams` and `POST /api/predict`.
- `prototype.html` — approved layout, built by `tools/build_mockup.py` (which
  writes `tools/mockup.html`; copy it over). Regenerating reproduces the
  committed file byte for byte. Port markup/CSS from here.
- `predict_matches.py` — benchmark only, not the serving path. Chronological split.
- `refresh_data.py` — keeps `dataset/results.csv` current against upstream.
  Called by `get_model()`; see Commands for why it is not a cron job.
- `web/` — Vite + React + TS. `prototype.html` ported into `TeamPicker`,
  `OutcomeBar`, `ScoreGrid`, `Markets`, `H2H`, `Form`. Vite proxies `/api` to
  port 8000, so the app never hardcodes a host. The grid-windowing maths lives in
  `web/src/grid.ts` (not the `.tsx`) so `node --test` can run it without a
  framework.

**Next: Elo or rolling-form features** — see Deferred below.

## Locked decisions

**The numbers below were re-measured after the dataset moved to upstream
(2026-08-03) and are lower than the ones this file used to carry. That is the
data, not a regression** — see Data constraints. The old file listed the
stronger side as `home_team`, which flattered every metric.

Re-verified on 2026-11-17 against a refreshed `results.csv` (49,940 rows, 421
new matches since August). Re-run and corrected below: the split table, the
per-team home-advantage range, the dataset counts and the outcome rates — all
reproduced to within 0.01, and a few digits that were slightly off when first
written are fixed. **Not re-run:** the `is_neutral` delta (0.8969 → 0.8968) and
the arithmetic-vs-geometric comparison (0.8772 vs 0.8777). Those are August
figures; the conclusions they support do not turn on a third decimal place.

**Model — geometric blend, not arithmetic, weighted 0.9 to Poisson.** `_pool()`
in `model.py` combines Poisson and XGBoost via a log-opinion pool. An arithmetic
mean lets XGBoost's bad extreme-fixture behaviour through (San Marino at 10.2%
to beat Brazil). Measured on a chronological 80/20 split (5,174 held out, of
which 4,860 are scorable — the rest involve a team or competition unseen before
the cutoff): pool 0.601 acc / 0.877 log loss, vs Poisson alone 0.601 / 0.877 and
XGBoost alone 0.535 / 0.989. The baseline — predict the training class prior
every time, which calls every match a home win — is 0.477 / 1.051.

**XGBoost is kept for the competition selector, not for accuracy.** At weight
0.9 it is worth 0.0004 log loss, which would not justify a second model. It
stays because it is the only model that reads `tournament` — drop it and the
competition dropdown stops changing the prediction, which is the failure mode
the venue rule below exists to prevent. The weight was 0.5 on the old dataset;
XGBoost leant on the home-ordering artifact and lost most of its value without
it. If Elo lands and Poisson absorbs `tournament`, reopen this.

**`is_neutral` stays out of the XGBoost features — but the reason changed.** On
the old dataset the flag was a strength proxy (0.747 home win rate on neutral vs
0.508 otherwise) and XGBoost latched on hard enough to put Japan at 0.987
against Australia on neutral ground. Upstream has no such defect: neutral 0.416
vs non-neutral 0.508, which is what home advantage should look like. Re-measured
on upstream, adding the flag moves pooled log loss 0.8969 → 0.8968 and the
toggle still runs backwards on some fixtures. **It is no longer harmful, just
worthless.** Venue stays the Poisson `home` term's job.

**Team flag colours are never used for data encoding.** Measured over the 242
names in `countries_names.csv`: 100 teams (41%) fall below 3:1 contrast against
the dark panel, 48 below it on light, and 10,888 of 29,161 possible fixtures
pair two colours under 1.5:1 from each other — England `#FFFFFF` is 1.0:1 on the
light panel, Germany `#000000` is 1.3:1 on dark. Home/away therefore use the
fixed `--home` / `--away` theme tokens everywhere. Re-run the numbers before
reopening this.

**Team identity is the flag, colour is only the fallback.** `web/src/flags.ts`
maps 240 of 322 teams to a flag-icons code and is generated by
`web/scripts/build-flags.mjs` — **re-run it when `dataset/results.csv` changes**,
which is where the roster now comes from (`countries_names.csv` is only a colour
lookup, and covers 229 of the 322). The 82 without a flag are the CONIFA and
Island Games sides plus Zanzibar, Tibet, Kurdistan and Northern Cyprus; they
fall back to the bordered colour swatch, which is what `Flag.tsx` handles.
`gb-eng` / `gb-sct` / `gb-wls` / `gb-nir` mean the home nations get their own
flags rather than the Union Jack.

The generator splits CSV lines on commas without a parser. That is safe *only*
because `date,home_team,away_team` are the first three columns and contain no
commas, while `tournament` and `city` (which do) sit after them. A header assert
fails loudly if upstream ever reorders.

**Home advantage is per team, and it buys no accuracy.** The Poisson carries a
global `home` term plus a one-hot `home_team` block, so each side deviates from
the average instead of sharing one number. Measured on the chronological split:
global-only 0.8363 / 0.6307, per-team 0.8361 / 0.6309 — a paired improvement of
+0.0002 ± 0.0011, better on 49.5% of matches. **It is a modelling fix, not an
accuracy win; do not cite it as one.** It is kept because a single multiplier
for both Bolivia and Tonga is wrong on its face, and because
`home_advantage(team)` is now a real number the UI could show.

`HOME_BLOCK_SCALE = 0.4` is what makes it defensible. `PoissonRegressor` takes
one alpha for every coefficient, so the block is scaled to shrink it separately
(effect ∝ 1/s, penalty ∝ 1/s²). Unshrunk, Tonga scored 0.54× off five home
matches — worse at home — and the block spanned 0.54–2.31 for no metric gain.

As shipped (fit on all data) the range is **0.92–2.15, median 1.25 against a
global term of 1.254**, with only 6 of 322 teams below 1.0. The top is the
sanity check that matters: Bolivia 2.15, Guatemala 1.72, Ecuador 1.62 —
altitude and travel, not noise. `check_home_advantage_is_per_team` in
`test_model.py` guards the range, the median, and Bolivia's place at the top.

**The competition dropdown is grouped by confederation, not frequency-ordered.**
106 tournaments is unusable as a flat list. `tournament_region()` in `model.py`
sorts them into Friendly, World and the six confederations — Friendly first
because it is the default and a third of the dataset, then World, then the rest
A–Z, with names A–Z inside each group under an accent-blind key so
`Copa América` files beside `Copa America`. `/api/teams` returns
`[{region, tournaments}]` and the client renders `<optgroup>`s.

Classification is keyword-based and **order-sensitive**: cross-confederation
competitions are matched first so `Afro-Asian Games` is not caught by `asia`,
and bare `world cup` is matched last so combined qualifiers group under the
confederation that actually plays them. Upstream names competitions by
confederation acronym where the old dataset spelled them out, so both are
matched — `uefa` alongside `european`, `gold cup` alongside `concacaf`. Without
that, 79 of the 129 competitions present when this was measured fell into
"Other"; the file now carries 140.

61 entries are overridden by exact name after checking the team sheet, not the
name. Two reasons: genuinely cross-confederation events (`Island Games` runs
Bermuda to Greenland, `Coupe de l'Outre-Mer` spans CONCACAF/CAF/OFC, `Cup of
Ancient Civilizations` was China–Iran–Egypt), and substring collisions no
keyword can resolve — `Nations Cup` is the British Isles four while `Oceania
Nations Cup` is not, and `MSG Prime Minister's Cup` is Melanesian while a bare
`Prime Minister's Cup` ran Bahrain against Kenya. `check_tournament_groups`
fails if a new tournament matches nothing, which is the cue to classify it
rather than ship an "Other".

**λ is capped at 6.0.** Multiplicative Poisson explodes on extreme mismatches
(Brazil v San Marino solved to 10.6 expected goals). Costs zero measured log loss.

**Scoreline grid is sent whole (11×11).** The client windows it to the smallest
square covering 95% of the mass — lopsided fixtures peak well outside 0–5.

## Front-end conventions

- **No state library.** Server state is everything and there are two endpoints;
  `useState` plus one `usePrediction` hook covers it. Reach for TanStack Query
  when endpoints pass ~4 or cross-fixture caching starts to matter — not before.
- **No chart library.** Every visual is CSS: flex bars, a CSS-grid heatmap.
- **No combobox library either, and no `<datalist>`.** The team picker was
  `<datalist>`-backed until the popup had to match the field: a datalist's
  dropdown is drawn by the browser and **cannot be styled at all** — width,
  position and height are out of CSS's reach, so it renders as a narrow list
  detached from the input. `TeamPicker.tsx` is ~75 lines of hand-rolled
  combobox instead: filter, arrow keys, Enter, Escape, click-outside, ARIA
  roles. Reach for a library only if grouping or multi-select arrives.
- **Fonts: Roboto + Roboto Mono.** Sans for prose, mono for every number
  (`font-variant-numeric: tabular-nums`). **Icons: Font Awesome**, used only where
  they carry function, never as section decoration.
- **Self-host fonts, never CDN-link them.** The Artifact CSP blocks external
  hosts, so `<link>` to Google Fonts or the Font Awesome CDN silently falls back.
  In `prototype.html` they are inlined as base64 `@font-face` data URIs; Font
  Awesome is subsetted with `pyftsubset` to the glyphs used (204 KB → 1.4 KB).
  In `web/` they come from `@fontsource-variable/roboto`,
  `@fontsource-variable/roboto-mono` (families `Roboto Variable` /
  `Roboto Mono Variable`) and `@fortawesome/fontawesome-free`, all bundled by
  Vite. Only Font Awesome's `solid` stylesheet is imported.
- **`assetsInlineLimit: 0` in `vite.config.ts` is load-bearing.** flag-icons
  names ~540 SVGs and most sit under Vite's 4 KB inline threshold, so the
  default setting inlines the entire world into the stylesheet — 507 KB CSS
  instead of 116 KB. Emitted as files, a page fetches only the two flags it
  shows (verified in the network panel).
- **`.swatch` sets `background-color`, never the `background` shorthand.** The
  shorthand resets `background-image` and silently blanks the flag layered onto
  the same element.
- **Both themes.** Tokens on `:root`, redefined under
  `@media (prefers-color-scheme: dark)` and both `:root[data-theme="..."]` blocks.

## Data constraints

`dataset/results.csv` is [martj42/international_results](https://github.com/martj42/international_results)
verbatim — nine columns: `date, home_team, away_team, home_score, away_score,
tournament, city, country, neutral`. 25,879 matches since 2000, 322 teams,
140 competitions. `refresh_data.py` keeps it current; do not hand-edit it.

A refresh can add competitions as well as matches: the November 2026 refresh
relabelled ~420 rows that upstream had previously filed as `Friendly` into named
invitationals (`China Cup`, `LG Cup`, `Four Nations Tournament`), which is what
`check_tournament_groups` exists to catch. Expect to classify a handful after
any long gap.

**It replaced `all_matches.csv`, which was a different compilation, not an older
snapshot.** That file had 927 Olympic matches upstream excludes by policy, used
historical team names (`Ireland` for pre-1921 Northern Ireland, `Czechia`,
`Burma`), and — the reason the swap mattered — **listed the stronger side as
`home_team`**. Over the shared window (2000-01-04 to 2026-03-31) it showed
home/draw/away of 0.575/0.236/0.189 where upstream shows 0.481/0.233/0.286 —
a 9-point home/away swing with the draw rate untouched, which is the signature
of mis-ordered fixtures rather than a different sport. Every metric measured on
it was flattered. Do not compare current numbers to pre-2026-08-03
ones; they are different problems.

Upstream carries ~70 CONIFA and Island Games sides (Padania, Sápmi, Yorkshire,
Shetland) the old file lacked. **Kept deliberately** — taking upstream whole
means no filter rule to maintain and no risk of silently dropping a real
nation. They have no flags, so they land on the colour swatch.

**No cards, shots, possession or xG exist in `results.csv`.** Do not design UI
for them and do not claim to predict them. Club/league teams are likewise out of
scope — this dataset is internationals only.

Upstream also publishes `shootouts.csv` (penalty shootout winners) and
`goalscorers.csv` (scorer and minute, ~3.2 MB). **Neither is fetched yet.**
`goalscorers.csv` is the only route to any player-level or timing feature this
project has; if "stats" ever means more than goals, it starts there.

## Commands

```bash
.env/bin/python test_model.py          # model sanity checks
.env/bin/uvicorn api:app --reload --port 8000
.env/bin/python refresh_data.py        # fetch upstream if stale; --force, --check
.env/bin/python predict_matches.py     # benchmark, writes results/
npm --prefix web run dev               # front end on :5173, needs the API up
npm --prefix web test                  # grid-window checks, node --test
npm --prefix web run build             # tsc -b && vite build
node web/scripts/build-flags.mjs       # regenerate web/src/flags.ts
```

**Data refresh runs at startup, not on a cron.** `get_model()` calls
`refresh_data.refresh()` before fitting, and only fetches when the local copy is
more than 3 days old. That is the only moment a refresh can take effect: the fit
is `@lru_cache`d for the process, so a cron rewriting the CSV at 3am is
invisible to a server that has been up since Tuesday. The cadence matches the
data — in 2025, March/June/September/October/November carried ~90% of matches
while February had 4 and April had 2. Failures are non-fatal: the existing file
is kept and the app starts anyway. `certifi` is a real dependency here — a stock
python.org macOS install has no trust store and `urlopen` fails
`CERTIFICATE_VERIFY_FAILED` where `curl` works.

Virtualenv is `.env/` (not `.venv/`). `.claude/launch.json` holds both servers.

## Deferred, in priority order

1. **Elo or rolling-form features** — the biggest accuracy win still available,
   ~20 lines, feeds both models.
2. **Venue — now unblocked one level further than it was.** `results.csv`
   carries both `country` (host nation) and **`city`, populated on every row**
   (49,940 at the last refresh), and no feature uses either. City is not a stadium, but it is where
   the altitude signal actually lives — La Paz, Quito, Mexico City — so a host
   picker keyed on city would move the numbers, not just the label. This is the
   natural partner to the per-team home-advantage term already in the Poisson.
   Do it after Elo.

   *Specific stadium* remains blocked: no ground-level column exists upstream,
   and results feeds generally do not carry one. Do not build a stadium dropdown
   that does not move the prediction.
3. Model persistence via joblib — currently fits on first request (~2s measured).
4. URL search params for shareable predictions (needs a router).
5. Club/league support — blocked on a dataset.
